# خبير الشواهد: بنية مبسطة وقابلة للنقل

## قرار المنتج

يبقى التطبيق في نسخته الأولى **محليًا أولًا**. ينفذ المعلم رحلة واحدة مختصرة: يلتقط الشاهد، يضيف سياقه، يكتب انعكاسًا اختياريًا، يجمع الحزمة، ثم ينشئ مشاركة مقيدة. لا يحتاج هذا المسار إلى قاعدة بيانات كي يبدأ؛ إذ تحفظ المسودة تلقائيًا في المتصفح، ويمكن تصديرها واستيرادها بصيغة JSON. هذه البساطة تقلل التكلفة والصيانة وتضمن استمرار الاستخدام عند ضعف الاتصال.

## حدود نموذج البيانات

| الكيان | الغرض | أقل الحقول اللازمة |
| --- | --- | --- |
| `user` | مالك الشواهد عند تفعيل الحسابات. | `id`, `display_name`, `email`, timestamps |
| `evidence` | شاهد واحد مستقل. | `id`, `owner_id`, `title`, `category`, `period`, `reflection`, `file_key` |
| `bundle` | ملف أداء مرتب. | `id`, `owner_id`, `title`, `period` |
| `bundle_item` | ترتيب الشواهد داخل الحزمة. | `bundle_id`, `evidence_id`, `position` |
| `share_link` | مشاركة مؤقتة قابلة للسحب. | `id`, `bundle_id`, `access_mode`, `token_hash`, `expires_at`, `revoked_at` |

لا يحتاج الإصدار الأول إلى جداول للمدارس أو المديرين أو نماذج التقييم؛ فهذه تُضاف فقط عند ظهور حاجة مثبتة في اختبار المدارس. المخطط التنفيذي موجود في [portable-schema.sql](./portable-schema.sql).

## طبقة بيانات مستقلة

يعتمد واجه التطبيق على عقد تخزين واحد في `client/src/lib/evidenceStore.ts`. المحول الحالي هو `localStorage` للنسخة التفاعلية. عند التحول إلى منتج متعدد الأجهزة، يستبدل المحول فقط بمستودع REST أو GraphQL، بينما تبقى مكونات الواجهة والنماذج كما هي.

| المرحلة | التخزين | ما الذي يتغير؟ |
| --- | --- | --- |
| النموذج والتجربة المغلقة | `localStorage` + ملف JSON | لا توجد خدمة خلفية أو حسابات. |
| المنتج الفردي | SQLite محلي أو قاعدة بيانات مستضافة بسيطة | إضافة حساب اختياري ومزامنة مسودات. |
| المدارس المتعددة | PostgreSQL وواجهة API مستقلة | تفعيل الحسابات، الملفات، وروابط المشاركة المؤقتة. |

## واجهة API مستقبلية صغيرة

تظل الواجهة الخلفية اختيارية ومنفصلة. عند الحاجة، تكفي نقاط نهاية قليلة: `GET/POST /evidences`، و`PATCH/DELETE /evidences/:id`، و`GET/POST /bundles`، و`PATCH /bundles/:id/items`، و`POST /bundles/:id/share-links`، و`POST /share-links/:id/revoke`. تستخدم الملفات مفاتيح تخزين محايدة داخل `file_key`؛ ويمكن ربطها بأي مخزن S3-compatible أو تخزين محلي مؤمّن.

## قابلية النقل والنشر

هذا المشروع تطبيق React/Vite ثابت. لا يعتمد في وقت التشغيل على خدمة منصة أو قاعدة بيانات أو مفتاح خفي. ينشئ الأمر `pnpm build` ملفات ثابتة في `dist/public` ويمكن رفعها إلى أي استضافة ملفات ثابتة أو خادم Nginx أو CDN. تحتفظ النسخة المحمولة بالمتغير الاختياري `VITE_API_BASE_URL` فقط عند ربط API خارجي مستقبلًا.

| خطوة النقل | التنفيذ |
| --- | --- |
| تجهيز الكود | `git clone` ثم `pnpm install`. |
| تشغيل محلي | `pnpm dev`. |
| بناء مستقل | `pnpm build`. |
| النشر | رفع محتويات `dist/public` إلى الاستضافة المختارة. |
| ربط الخلفية لاحقًا | تعيين `VITE_API_BASE_URL` إلى نطاق API الخاص بك وبناء التطبيق مرة أخرى. |

## قواعد الاعتمادية والصيانة

يحفظ التطبيق كل تعديل تلقائيًا محليًا، ويتيح نسخة احتياطية قابلة للقراءة والاستيراد. تعتمد مشاركة الحزمة في الإنتاج على رموز سرية مخزنة بصيغة hash فقط، وتفحص حالة السحب وتاريخ الانتهاء عند كل فتح للرابط. لا توضع مفاتيح مزود التخزين أو قاعدة البيانات في الواجهة الأمامية. ويكون الاستبدال التقني محصورًا في محول التخزين وطبقة API، لا في شاشات المعلمين.
