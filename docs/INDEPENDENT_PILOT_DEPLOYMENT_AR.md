# حزمة النقل والنشر المستقل

## الهدف والنطاق

تجعل هذه الحزمة **خبير الشواهد** جاهزًا للنشر كتطبيق ويب تقدمي ثابت على نطاق مملوك لك، من دون خادم تطبيق أو قاعدة بيانات أو حسابات مستخدمين. تظل الشواهد والصور والنسخ الاحتياطية في المتصفح وعلى جهاز المستخدم؛ ولا ينقل النشر الثابت هذه البيانات إلى الاستضافة.

> **تنبيه قبل تغيير النطاق:** تخزين المتصفح مرتبط بالنطاق. على المستخدم الحالي تنزيل «نسخة شاملة» من الإعدادات قبل فتح النسخة الجديدة، ثم استيرادها في النطاق الجديد. لا يمكن نقل IndexedDB تلقائيًا بين نطاقين مختلفين.

## ما أُضيف إلى المشروع

| الملف أو الأمر | الغرض |
|---|---|
| `pnpm run build:static` | يبني واجهة Vite وPWA فقط إلى `dist/public` من دون خادم Express. |
| `client/public/_redirects` | يعيد مسار `/director` وبقية مسارات React إلى `index.html` عند فتحها مباشرة. |
| `client/public/_headers` | يضيف رؤوس أمان خفيفة وتخزينًا طويلًا للأصول ذات الأسماء المشتقة، مع إبقاء Service Worker وManifest قابلين للتحديث. |
| `.nvmrc` | يحدد Node.js 22 لبيئة البناء المتسقة. |

ملفات `_redirects` و`_headers` داخل مجلد الأصول العام تُنسخ إلى ناتج البناء ويقرأها Cloudflare Pages عند النشر [1] [2].

## خطوات إنشاء مستودع مستقل

أنشئ مستودع GitHub **خاصًا** باسم مثل `khabir-alshawahid`، ثم صدّر كود المشروع الحالي إليه من واجهة المشروع أو من تنزيل ZIP. لا تنسخ ملفات البيئة أو مجلدات الاعتمادات أو المخرجات. لا يتطلب هذا الإصدار أي سر أو متغير بيئة للتشغيل الثابت.

| يُرفع إلى GitHub | لا يُرفع إلى GitHub |
|---|---|
| `client/`, `scripts/`, `docs/`, `package.json`, `pnpm-lock.yaml`, `vite.config.ts` | `node_modules/`, `dist/`, `dist-static/`, `.env*`, سجلات التطوير، ملفات النسخ الاحتياطية للمستخدمين |

بعد فتح المستودع على جهاز التطوير، شغّل:

```bash
corepack enable
pnpm install --frozen-lockfile
pnpm check
pnpm test
pnpm run build:static
```

لا تستخدم `vite preview` بوصفه خادم إنتاج؛ هو مخصص لمراجعة ناتج البناء محليًا فقط [3].

## نشر Cloudflare Pages

في Cloudflare: **Workers & Pages → Create application → Pages → Connect to Git**، ثم اختر مستودع GitHub. استخدم الإعدادات التالية:

| الإعداد | القيمة |
|---|---|
| Production branch | `main` |
| Build command | `pnpm run build:static` |
| Build output directory | `dist/public` |
| Root directory | `/` |
| Node.js | `22` |
| Variables / Secrets | لا شيء لهذا الإصدار المحلي أولًا |

تدعم Cloudflare Pages الربط بمستودع GitHub وتبني وتنشر التغييرات تلقائيًا مع كل دفع إلى الفرع؛ كما توفر روابط معاينة للفروع وطلبات السحب [4]. وتوضح وثائق Vite أن مخرج البناء الافتراضي قابل للنشر على الاستضافة الثابتة، مع ضرورة استخدام مسار المخرج الفعلي في إعدادات المنصة [3].

بعد نجاح أول بناء، اربط نطاقًا خاصًا مثل `app.khabir-alshawahid.sa` من إعدادات Pages. اترك رابط `pages.dev` للاختبارات فقط، ثم فعّل الإنتاج على النطاق الخاص بعد اختبار رحلة النسخ الاحتياطي والاستعادة.

## قائمة فحص الاختبار الميداني

| التوقيت | ما يُختبر | معيار القبول |
|---|---|---|
| قبل الدعوة | نسخة شاملة ثم استعادة على نطاق المعاينة | عودة الشواهد والصور والشعارين وإعدادات الغلاف دون فقد. |
| الأسبوع الأول | تثبيت PWA على Android وWindows | يفتح التطبيق من الأيقونة ويعمل بعد قطع الشبكة. |
| الأسبوع الثاني | إضافة شواهد وصور وتصدير PDF وWord | المخرجات العربية RTL سليمة والملفات محلية. |
| الشهر الأول | تجربة المعلم والمدير | انتقال ملف PDF ومراجعته وتقرير Excel/PDF دون رفع تلقائي. |
| قبل الإطلاق العام | مراجعة الخصوصية والعمل دون اتصال | لا يوجد رفع تلقائي، وتظل جميع وظائف الإضافة والتعديل والتصدير والاستعادة متاحة. |

## حدود المرحلة الحالية

يعمل التطبيق محليًا من دون حسابات أو خادم تطبيق أو آلية صلاحية زمنية. اجمع ملاحظات الاستخدام عبر قناة اختيارية خارج التطبيق، مع عدم طلب ملفات الشواهد أو النسخ الاحتياطية من المعلمين. لا يتغير مبدأ بقاء محتوى المدرسة محليًا.
